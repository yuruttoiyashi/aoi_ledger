# 青色帳簿 UI/UX リデザイン仕様書

## 1. 目的と前提

「青色帳簿」を、毎日の仕事とお金を静かに整えられる、PC向けの個人会計ダッシュボードへリデザインする。今回の対象は画面構成、情報設計、HTMLの見通し、CSS、表示用の集計であり、会計の意味や保存契約を作り直すことではない。

既存の `src/domain/accounting.js`、`src/domain/csv.js`、`src/storage.js` が担う会計計算・CSV解釈・保存処理を基準実装として扱う。UIから扱いやすくするためのDOMイベントや表示用ヘルパーの追加は許可するが、既存データを別形式へ移行する処理は追加しない。

## 2. 守る契約（変更しないもの）

- localStorageキー `aoi-ledger-state-v1`
- stateの配列・設定の形（`sales`、`expenses`、`importedTransactions`、`settings`）
- レシート用IndexedDBのDB名 `aoi-ledger-receipts`、object store名 `receipts`
- バックアップJSONの `version: 1`、`state`、`receipts` 構造
- `buildJournal` の仕訳ルール、`expenseBusinessAmount` の家事按分、`monthlySummary` の計算
- CSVの既存ヘッダー、列の意味、BOM付き出力、既存インポートの解釈
- 入力時の会計ルール：現金売上、現金経費、私用カードの事業主借、事業用口座

表示ラベルを変更しても、保存時のキーや値（たとえば `personal_card`）は変更しない。移行ロジックやダミー会計データは作らない。

## 3. 利用者と主要タスク

利用者は自分専用の個人事業主。PCの1440×900前後で、次の作業を短い視線移動で済ませる。

1. 今日または選択月の売上を確認する
2. 経費を1件登録し、支払方法・事業利用割合・レシートを残す
3. 実データから生成された仕訳を確認する
4. カードCSVを取り込み、事業・私用・按分を選んで経費へ反映する
5. バックアップとCSVを必要なタイミングで出力する

新規利用者に借方・貸方の入力を要求せず、会計の結果を確認したいときだけ仕訳帳へ進める。

## 4. 情報設計

### 4.1 アプリシェル

- 左に固定サイドバー（幅220px、1024pxでも本文を圧迫しすぎない）。
- 右にトップバーと本文。本文は `margin-left` でサイドバー分を確保し、最大幅を設けて1440pxで左右に呼吸できる余白を作る。
- サイドバーとトップバーは常に同じ視覚言語を使い、各ページは共通の `.panel` / `.card` を使う。
- 現在ルートの再描画方式と既存イベントバインド方式は維持し、DOM構造変更後も `bindCommon` / `bindView` の責務を明確にする。

### 4.2 サイドバー

上部に細い線画の葉アイコン、アプリ名「青色帳簿」、コピー「やさしい会計で、いい明日をつくる。」を置く。文字記号だけに依存しないよう、CSSまたはインラインSVGの単純な線画アイコンを使う。

メニュー順は次の通り。既存のカードCSV機能は「カードCSV」として残す。

- ダッシュボード
- 売上
- 経費
- 車両費
- 仕訳帳
- カードCSV
- バックアップ
- 設定

選択中は淡いセージ背景と濃いセージ文字、未選択はチャコール〜補助文字色とする。車両費ページは既存の `category === '車両費'` の経費を見せ、登録ボタンから経費入力へ進める。車両費専用の新しい保存データや会計仕訳は作らない。

下部の植物モチーフは低コントラストで、ナビゲーションや操作要素より目立たせない。

### 4.3 トップバー

- 横長の「取引・メモを検索」欄
- 通知アイコン。通知は既存データから導ける未処理カード明細数などに限定し、見せるものがなければ静かな状態にする
- プロフィール表示「ゆみちゃん」。これは表示用コピーであり保存データではない。屋号が設定されている場合は補助ラベルとして表示する

検索文字列は画面表示中だけの一時状態とし、localStorageやバックアップに保存しない。売上・経費・仕訳帳・カードCSVの表示リストを日付、摘要、店舗、メモ、勘定科目、支払方法などの既存表示データで横断的に絞り込む。検索結果がない場合は入力を消す導線を含む空状態を出す。

### 4.4 ダッシュボード

上部は挨拶エリアと月選択をまとめる。

- 「おかえりなさい、ゆみちゃん」
- 「今日の丁寧な記録が、あしたの安心につながります。」
- 右側に選択月、日付、短いメッセージ
- 背景にはごく薄い葉の輪郭や光の円を置けるが、本文のコントラストを下げない

#### KPIカード4枚

カードの順序と値は実データから次のように定義する。

| 表示 | データ | 補助表示 |
| --- | --- | --- |
| 今月売上 | `monthlySummary(...).sales` | 売上登録日数 |
| 今月経費 | `monthlySummary(...).expenses` | 売上比の経費率 |
| 概算利益 | `monthlySummary(...).profit` | 平均日商などの実データ補助 |
| 積立目安 | `monthlySummary(...).reserve` | 設定された積立率 |

既存の `available` は必要なら積立後の残額として補助テキストに出す。スパークラインは選択月の実際の日別売上または経費から生成し、データがない場合は線を描かず「入力すると推移が表示されます」とする。サンプル値・乱数・会計計算へ混ぜるダミー値は使用しない。

#### 中央〜下段

- 中央の大きな「仕訳帳」カード：見出し、説明、仕訳検索、CSV出力、新規入力の操作を置く。新規入力はセージ色のプライマリーボタン。現行アプリは売上・経費から仕訳を自動生成するため、新規入力は売上または経費登録へ案内する。
- 下段左の「最近の経費」：選択月を優先して直近の経費を表示。日付、内容、勘定科目pill、按分後の必要経費額を出す。
- 下段右の「今月の入力状況」：実データの記録日数をドーナツで表示し、売上入力日数、経費入力日数、レシート添付数を意味のある分母で進捗表示する。

入力状況の分母は次で固定する。

- ドーナツ：`売上または経費がある異なる日数 / 選択月の日数`
- 売上の入力：`売上がある異なる日数 / 選択月の日数`
- 経費の入力：`経費がある異なる日数 / 選択月の日数`
- レシートの整理：`receiptId がある経費数 / 経費数`（経費0件なら0%）

各バーにはパーセントだけでなく「n日」「n件」を添える。月の全日を入力することを暗黙の目標にせず、0件時には「最初の1件から始めましょう」、記録があるときには「いいペースです」と表示する。

## 5. 各ページの構成

### 売上

フォームと一覧を同じ余白規則のパネルで構成する。1日分の売上合計、チップ、出勤先、メモを入力する現行項目を残す。保存後は同じ画面に戻り、成功トーストと一覧更新を行う。

### 経費

内容、金額、支払先、勘定科目、支払方法、事業利用割合、レシート、メモの現行項目を維持する。金額・按分後金額を右揃え、勘定科目は淡いpill、支払方法は読みやすい補助ラベルにする。フォームの説明文で「私用カードは事業主借」「按分後が必要経費」と伝える。

### 車両費

`車両費` の既存経費だけを対象にした見通し画面。月フィルター、件数、支出額、按分後必要経費額、一覧を表示し、登録操作は既存経費フォームへ遷移する。`vehicleDefaultRatio` は設定値として表示・説明にのみ使い、既存の保存時挙動を変えない。フィルターは一時状態で、保存形式に影響しない。

### 仕訳帳

大きなパネルの中心に自動生成された仕訳テーブルを配置する。日付、摘要、借方、貸方、金額を現行の `buildJournal` の結果から表示し、金額は右揃え。検索、CSV出力、新規入力導線をヘッダー右に置く。仕訳を直接編集・追加する機能は作らない。

### カードCSV

既存のCSV選択、取込、未処理・事業・私用・按分の変更、科目・割合編集、経費反映、取込消去を残す。テーブルは行間を広げ、状態を色だけでなく文字でも伝える。

### バックアップ / 設定

既存のJSONバックアップ復元、売上・経費・仕訳CSV出力、設定保存を機能そのまま再配置する。復元や消去のような重要操作は二段階にせず、既存の確認処理を保ちながら誤操作を視覚的に防ぐ。

## 6. ビジュアルシステム

CSS変数を一元化し、ページごとの色の独自定義を避ける。

```css
:root {
  --bg: #f6f5ef;
  --surface: #fffdf9;
  --surface-strong: #ffffff;
  --text: #303732;
  --text-soft: #737a74;
  --border: #e5e2d9;
  --sage: #7e9f84;
  --sage-dark: #66856d;
  --sage-soft: #dde9df;
  --sage-pale: #eff5ef;
  --beige-soft: #f2ece2;
  --blue-soft: #e8eef0;
  --pink-soft: #efe2e5;
  --danger: #a76368;
  --radius-md: 16px;
  --radius-lg: 22px;
  --radius-xl: 28px;
  --shadow-sm: 0 5px 18px rgba(40, 50, 43, 0.04);
  --shadow-md: 0 12px 30px rgba(40, 50, 43, 0.06);
}
```

- 基本背景は明るいアイボリー、カードはほぼ白。
- セージを選択・主要操作・グラフに使い、補助色はpillや状態の差分に限定する。
- 影はカードの存在を示す程度。強いグラデーションや濃い境界線を使わない。
- `Yasashisa Gothic`, `Noto Sans JP`, `Yu Gothic`, `Hiragino Sans`, `sans-serif` の順でフォールバックする。
- 本文14〜15px、見出しは十分な行間、金額は数字の桁を読みやすくする。全角・半角を混在させず、既存の円フォーマットを使う。
- カード角丸は20〜26px、入力は16px前後、カード間は18〜24px。

## 7. コンポーネントとインタラクション

- `appShell`：ブランド、ナビ、トップバー、共通トースト、共通モーダルを描画する。
- `panel` / `metric-card` / `btn` / `field` / `table-wrap`：全ページで共通化する。
- hoverは背景色や境界線がごく軽く変わるだけにする。派手なアニメーションは使わない。
- focus-visibleはセージの輪郭と薄いfocus ringを出す。
- 非同期のレシート表示・バックアップ・復元・CSV取込は、処理中の操作を見失わない短い状態表示を出す。
- モーダルは閉じるボタン、背景クリック、Escapeキーで閉じられるようにし、画像にはファイル名と代替テキストを出す。
- 削除・復元は既存の確認ダイアログとエラートーストを維持する。
- 表示用文字列は既存の `esc` を通し、検索文字列をHTMLへ直接差し込まない。

## 8. レスポンシブとアクセシビリティ

- 1440×900を基準に、本文最大幅と余白を調整する。
- 1024px前後ではKPIを2列、下段を1列へ落とし、サイドバー220pxとテーブルの横スクロールを許容する。
- 画面全体に意図しない横スクロールを作らない。表だけが必要時に横スクロールする。
- すべての入力にlabelを関連付け、ボタンの目的を日本語で明記する。
- セージだけで状態を表現せず、文字・アイコン・形状も併用する。
- キーボードでナビ、検索、フォーム、モーダルを操作できる。`prefers-reduced-motion` では遷移を抑える。

## 9. 変更範囲と実装順

1. 既存UIテストを新しいCSSトークンと主要構造へ更新し、先に失敗を確認する。
2. 実データから入力状況・日別スパークラインを計算する純粋な表示ヘルパーとテストを追加する。会計ドメインの計算は呼び出さない。
3. `styles.css` をトークン、シェル、カード、テーブル、フォーム、レスポンシブの順に再構成する。
4. `src/app.js` のシェル、ダッシュボード、ナビ、検索、車両費画面を更新する。
5. 売上・経費・カードCSV・仕訳帳・バックアップ・設定のDOMを共通パネルへ再配置する。保存ハンドラとCSV処理の意味は維持する。
6. `index.html` のメタ情報・タイトルを確認し、`dist` を既存ビルドで再生成する。

既存ドメイン・保存・CSVモジュールは、UI変更に不要な限り編集しない。既存のinline styleは共通クラスへ寄せる。

## 10. 検証計画

自動検証：

- `npm test`
- `npm run check`
- `npm run build`
- `npm run dev` 起動後にトップページを取得できること
- 既存の会計・CSV・ツールテストがすべて通ること
- UIテストがセージ／アイボリーのトークン、固定シェル、month picker、主要導線を検査すること
- 表示用入力状況ヘルパーが月の日数、重複日、レシート数、0件状態を正しく計算すること

手動またはブラウザ確認：

- 既存データを読み込んだ状態でダッシュボード、売上、経費、仕訳帳、車両費を表示できる
- 売上登録で既存の売上データが追加され、自動仕訳が現金 / 売上高になる
- 経費登録で現金、私用カード、事業用口座の既存仕訳と家事按分が変わらない
- レシート画像を添付・表示・削除できる
- CSV出力の既存ヘッダーと列が保たれる
- CSV取込の分類・按分・経費反映が動く
- JSONバックアップの保存・復元で既存データとレシートが残る
- 1440×900と1024px幅でレイアウトが崩れず、表だけが必要時に横スクロールする

## 11. 完成条件

デザインはアイボリー × セージを主役にし、ナチュラルでも古くなく、やさしくても幼くないこと。主要操作が見つけやすく、実データのない箇所に見せかけの会計数値を出さないこと。上記の既存機能と自動検証を満たし、保存形式・会計ロジック・CSV契約に差分がないことを完成条件とする。
